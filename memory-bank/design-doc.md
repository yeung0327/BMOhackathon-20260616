# 产品设计文档 — Roots & Shoots 知识宇宙

## 1. 产品概述

**产品名称**：Roots & Shoots（根与芽）

**一句话定位**：将静态知识库转化为可交互、可探索、可对话的知识宇宙。

**核心价值**：任何员工上传文档后，即可通过 3D 知识图谱 + 智能问答，快速看清事件/概念间的因果链条，实现知识的可视化探索。

**项目性质**：百度 BMO 黑客松参赛作品，单人 + AI 协作完成。

---

## 2. 目标用户

所有员工。不限角色，任何人都可以上传文档并进行知识探索。

**典型场景**：
- 策划人员：上传历史活动文档，看清成功活动之间的因果关联
- 新员工：通过图谱 + 对话快速了解业务知识脉络
- 技术人员：上传 API 文档，理清系统间依赖关系

---

## 3. 技术架构

基于开源项目 **llm-graph-builder**（Neo4j Labs）Fork 定制。

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | React + TypeScript + Vite | Fork 官方前端，深度定制 UI |
| 后端 | Python + FastAPI | 直接使用官方后端，基本不改 |
| 数据库 | Neo4j AuraDB（免费实例） | 存储知识图谱 |
| LLM | DeepSeek API（deepseek-chat，OpenAI 兼容格式） | 实体抽取 + 智能问答 |
| 图谱可视化 | Neo4j 官方图谱组件（内置于前端） | 节点关系渲染 |
| 部署 | Docker Compose 本地运行 | localhost 演示 |

---

## 4. 功能设计

### 4.1 文档上传与实体抽取

| 项目 | 说明 |
|------|------|
| 支持格式 | PDF、Markdown、HTML、纯文本 |
| 抽取方式 | LLM 自动抽取实体与关系，不预设类型 |
| 存储 | 抽取结果写入 Neo4j（节点 + 关系） |

### 4.2 关键词搜索 + 探索式浏览（P0）

**交互流程**：
1. 用户在搜索框输入关键词
2. 系统查询 Neo4j，返回以命中节点为中心的 **2 跳子图**
3. 图谱区域渲染该子图
4. 用户点击子图中任意节点 → 以该节点为新中心，重新查询 2 跳子图
5. 循环步骤 3-4，实现层层深入探索

### 4.3 智能问答侧边栏（P0）

| 项目 | 说明 |
|------|------|
| 对话模式 | 多轮对话，保留历史上下文 |
| 检索策略 | GraphRAG（graph + vector 混合检索） |
| 答案来源 | 展示回答所引用的节点/文档 |
| 图谱联动 | 答案中提及的实体，在主图区高亮显示 |

### 4.4 节点详情（P0）

点击节点弹出详情卡片，展示：
- 节点名称
- 节点类型（LLM 自动标注）
- 关联属性（时间、来源文档等）

## 5. 视觉设计

| 元素 | 设计方向 |
|------|----------|
| 整体风格 | 深色主题，宇宙/科技感 |
| 配色 | 深色背景（#0a0a1a 类）+ 霓虹高亮色 |
| 节点 | 按类型着不同颜色，带光晕/发光效果 |
| 连线 | 带方向指示，关系类型标注 |
| 品牌 | 融入百度如流品牌元素（Logo、文案） |
| 侧边栏 | 深色风格对话界面，气泡式消息展示 |

---

## 6. 创新点（相对于原版 llm-graph-builder）

1. **视觉重塑**：从默认的白色工具风格改为深色宇宙主题，提升演示冲击力
2. **场景聚焦**：围绕"知识探索"场景重新包装（文案、引导流程）
3. **探索式交互**：点击节点即可层层深入，而非仅支持搜索
4. **问答-图谱联动**：答案中的实体在图谱中实时高亮

| 标准 | 验收条件 |
|------|----------|
| 后端可用 | Docker 启动后，能上传文档并成功抽取实体关系 |
| 图谱展示 | 输入关键词后能看到节点和连线的可视化子图 |
| 探索浏览 | 点击节点能以新中心展开子图 |
| 问答功能 | 多轮对话正常，答案基于图谱数据 |
| 联动高亮 | 问答结果中的实体在图谱中被高亮 |
| 视觉效果 | 深色宇宙风格，演示效果佳 |
